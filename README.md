# payload (`pld`)

Terminal tool for creating, building, inspecting, and validating tables
for embedded systems, with input/output formats extensible via plugins.

## Pipeline

```
source (.c | .raw | ...) → [Reader plugin] → TableIR → [Writer plugin] → output (.o | .bin | ...)
```

## Documentation

- **[src/payload/docs/USAGE.md](src/payload/docs/USAGE.md)** — user guide: every command with

The same guides are bundled with the installed package and browsable
even without a local repository, from the "Documentation" section of `pld serve`.

## Installation (development)

```bash
pip install -e ".[dev]"
pld --version
```

## Quick start

`payload` ships no reader/writer of its own — every project brings its own
plugins (see [Example plugins](#example-plugins) below). From a checkout of
this repo:

```bash
pld init
pld plugin install examples/plugins/raw_text.py
pld plugin install examples/plugins/bin_writer.py
pld doctor
pld build example_table.raw --to bin
```

From outside the repo, `pld plugin install` also accepts a raw URL to one of
the files under `examples/plugins/` (e.g. a raw link to this repo on your
internal git host), or just copy the file by hand into a project's `plugins/`
folder — see [src/payload/docs/PLUGINS.md](src/payload/docs/PLUGINS.md).

## Web UI (`pld serve`)

`pld serve` starts a local web server with a graphical interface for
the same operations available on the terminal (build, inspect,
validate, browse the documentation). It requires the optional `serve`
extra:

```bash
pip install ".[serve]"    # or "-e .[serve]" for a development install
pld serve
```

## Tests

```bash
pytest
```

`pytest-cov` is configured (on-screen report). The suite is at 100%
line coverage. Core tests use fake in-memory plugins (`tests/fakes.py`)
or mocked subprocesses and don't require a compilation toolchain;
`tests/test_c_source_and_obj.py` and
`tests/test_cli_smoke.py::test_c_source_to_obj_via_cli` are the only
ones that use real `gcc`/`objcopy` (integration, not needed for
coverage) and are skipped automatically if unavailable.

## Build and distribution

```bash
python -m pip wheel . -w dist/ --no-deps --no-build-isolation
pip install dist/payload-0.1.0-py3-none-any.whl
```

The wheel is `py3-none-any` (no compiled dependency) — the exact same
wheel installs anywhere, see
[src/payload/docs/USAGE.md](src/payload/docs/USAGE.md#corporate-environmentsclosed-network) for
offline/corporate scenarios.

For a `pip`-free distribution (a single `pld.exe` on Windows, with
Python and dependencies already bundled in), see
[src/payload/docs/USAGE.md](src/payload/docs/USAGE.md#standalone-exe-distribution-windows).


## Example plugins

`payload` itself has no built-in reader/writer — every project owns its
plugins (a `plugins/` folder, no `pip install` needed, see
[src/payload/docs/PLUGINS.md](src/payload/docs/PLUGINS.md)). These reference
implementations live in [examples/plugins/](examples/plugins/) (not part of
the installed package) and install with `pld plugin install
examples/plugins/<file>.py`:

- `raw_text.py` — minimal text format with comments
- `csv_reader.py` — structured CSV, with offset/gap handling
- `c_source.py` — compiles a `.c` file (real toolchain, configured via `[plugin.c_source]`) and extracts the bytes of a data section
- `bin_writer.py` — raw binary dump
- `hex_writer.py` — standard Intel HEX format (checksum included)
- `obj_writer.py` — linkable `.o` with a dedicated section (configured via `[plugin.obj]`), `__start_`/`__stop_` symbols generated by the final linker
- `header_writer.py` — C header (`static const uint8_t[]`), zero toolchain configuration required
